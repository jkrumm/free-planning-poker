## Services

- **Next.js** (7720): UI, pages, non-realtime tRPC, Drizzle writes, auth, analytics tracking.
- **fpp-server** (7721): real-time room state (votes, users, flips), WebSocket actions, broadcast.
- **fpp-analytics** (7722): read-only analytics calculations and Parquet processing.

Room state lives in three places: MySQL (persistent), Bun server memory (authoritative, real-time), client Zustand store (synced over WebSocket). Update the authoritative source first, then propagate.

**Before a change that crosses a service boundary, Read `docs/development.md` §Cross-service changes** (the patterns and the protocol table).

## Commands

- Install: `bun install --frozen-lockfile`.
- Validate: `make check` mirrors `validate.yml` (format:check, lint, type-check, web `bun test`, build) and does not mutate. Run it before the first push and after every change. `bun run validate[:web|:server|:db|:shared|:analytics]` formats in place.
- Dev: `bun run dev` starts all services plus Logdy; `bun run dev:web` starts Next.js only. Suggest these to the user; do not start dev servers yourself.
- **IMPORTANT:** local Next.js builds need `SKIP_ENV_VALIDATION=1 bun run build`. Env is injected at runtime by `secrets-run run --env-file=apps/web/.env.tpl`, not at build time.
- No `.env.tpl` holds an `op://` ref, so `bun run dev` needs no 1Password and runs on the headless mini. Never `op read` or `op run` on the mini (it hangs); use `secrets-run`.
- Database and local rehydrate commands, local env values and URLs: `docs/development.md` §Build & Development Commands.

## Critical Rules

- **Pages Router, not App Router.** No `app/` directory, Server Components, async components, `export const metadata` or `next/navigation`. Use `apps/web/src/pages`, `getStaticProps` / `getServerSideProps`, `next/router`, and tRPC for API routes.
- **`fpp/*` import alias** for every internal import. Never `../../` paths.
- **Client env vars** need the `NEXT_PUBLIC_` prefix.
- **Zustand:** subscribe to a slice (`useRoomStore((s) => s.users)`), never the whole store.
- **WebSocket:** every message goes through `triggerAction()`.
- **ESLint suppressions** need a reason on the line above: `// eslint-disable-next-line rule-name -- why this is valid`. Before adding one, Read `docs/development.md` §ESLint & React 19 Linting for the valid patterns.

## Gotchas

- **WebSocket vs tRPC:** tRPC (HTTP) for room create, join, stats and name changes. WebSocket for votes, flips and presence.
- **User IDs** are anonymous: `nanoid(21)`, generated by each client and stored in localStorage.
- **Action queue:** `useWebSocketRoom.ts` queues actions sent while disconnected and sends them on reconnect.

## Error Handling (OpenTelemetry → HyperDX)

Sentry is gone. Telemetry goes OTEL → ClickStack/HyperDX. **Before writing or changing error handling, logging or telemetry, Read `docs/observability.md`**: the standards, severity tree, route and router patterns, event discipline and Logdy setup.

- `recordError(err, { component, action, extra }, severity)` for exceptions. Always pass `component` and `action`.
- `recordEvent(EVENT.X, attrs)` for typed domain events. Add the name to the `@fpp/shared/telemetry` registry first. Never emit per render, keystroke or tick.
- `metrics.*` is fpp-server only. Operator narration uses `log.warn` / `log.info`.
- Import the facade (`fpp/utils/app-error`). Banned outside it: `@opentelemetry/api-logs`, meters outside `telemetry.ts`, `@hyperdx/browser`, raw `fpp/utils/logger` on web, `captureMessage`, `addBreadcrumb`.
- Every attribute, event and metric name comes from `@fpp/shared/telemetry` (`ATTR` / `EVENT` / `METRIC`). No raw telemetry literals.
- tRPC routers never use try/catch or `recordError` (double capture). Wrap system errors with `.catch()` and `toCustomTRPCError`. Business errors (`NOT_FOUND`, `CONFLICT`, `BAD_REQUEST`, `UNAUTHORIZED`, `FORBIDDEN`) are plain `TRPCError` and are not captured. Never capture user-input errors.

## Shipping

- **Direct to master** only when all hold: one concern, small diff (dependency bump, typo, docs, config), lefthook passes, and no schema, shared-type or behaviour change. Everything else is a PR: `feat:`, non-trivial `fix:`, cross-service changes, `packages/db/src/schema.ts`, `packages/shared/src/room.actions.ts`. When in doubt, open a PR.
- **Commits:** `<type>(<scope>): <subject>`. Types: feat, fix, perf, refactor, docs, ci, chore, test, style, build. Scope is optional and must be `JK-<number>` if present. Header ≤ 80 characters, no trailing period (`commitlint.config.ts`, enforced by lefthook). Branch: `<type>/<short-description>`. No AI attribution anywhere.
- **PR:** `git push -u origin HEAD`, then `gh pr create --base master --fill` (or `/pr create`). Fold review fixes into the originating commit with `/commit --amend` and `git push --force-with-lease`.
- **Merge** is rebase-only (linear history), inside the merge window: `factory merge-lock --project free-planning-poker -- sh -c 'git fetch origin master && git rebase origin/master && git push --force-with-lease && <wait for CI on the pushed head> && gh pr merge <n> --rebase'`.
- **Deploy** is CI on every push to master: Vercel for web, `deploy.yml` (RollHook) for server and analytics. `make deploy` is a no-op. Manual redeploy: `gh workflow run deploy.yml -f service=<all|fpp-server|fpp-analytics|fpp-analytics-updater>`.
- **Verify:** `make verify` probes production (web, server, analytics) and exits non-zero when one is down. `make logs` tails the last 200 lines of prod fpp-server (`make logs SERVICE=fpp-analytics` for another).
- **Releases** are manual: `release.yml` or `/release-fpp`. Never edit `CHANGELOG.md` by hand. Branch protection, CI workflows and release rules: `docs/shipping.md`.
