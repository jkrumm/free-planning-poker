# load

The load test of docs/v9/evidence/load.md: `k6/` is the scenario k6 runs in a container, `run.ts` the Bun program that builds and starts the stack, runs k6, samples the containers and prints the numbers, `report.ts` what it computes, `compose.yml` and `proxy/` what the stack adds to `deploy/compose.yml`.

- **A run that has lost a vote stops at once** (`abortOnFail` on `votes_missing`, the one threshold that cannot recover): it fails in seconds instead of after its three and a half minutes. Keep that for a threshold that only ever gets worse; `errors` and the latency thresholds can still recover, so they run to the end.
- **Never against production or the beta host.** `make load` starts its own slot (500 rooms, about 3.5 minutes), `LOAD_SCALE=nightly` for 50 rooms, `HANDOFF=1` to replace the API container halfway, `LOAD_ROOMS=5` to try a change to the scenario in under two minutes, `NO_BUILD=1` to reuse the image of this commit. `make check-fast` type-checks the scenario but cannot run it.
- **`k6/` runs in k6's own runtime, not in Bun:** only `k6/*` modules and relative `.ts` files, no `node:` and no npm packages. Its tsconfig has no DOM, so `console` is declared in `globals.d.ts`. `k6/profile.ts` is shared with `run.ts` and stays pure data; the two sizes, the thresholds and the handoff's place in the run are there.
- **The mini's Colima VM has 4 CPUs and 2.5 GiB, shared with every other lead's containers, and mounts only the directories its config lists.** A bind mount of a repo file arrives empty, so the proxy and k6 images carry their files (`dockerfile_inline`) with `COPY --chmod`: a lead's worktree holds its files at 0600, which the images' unprivileged users (HAProxy, k6) cannot read, and a failed start costs the whole build. `--chmod` also applies to the destination directory, so k6's `/scripts` takes 0755. The stack takes about 1.2 GiB at 5,000 sockets (k6 750 MiB of it); check what else runs before the full profile.
- **A number is only as good as its generator.** At two CPUs the quota throttled k6 and the same server measured p99 598 ms instead of 6 ms, so k6 gets three and the report prints how often its quota held it back: read that line before believing a latency. The run also compares every acknowledged vote with the reveal that follows and counts a failed join, resume, command or delivery as an error; a timeout names the seats that never got the event.
- **The proxy is HAProxy** because it holds a WebSocket in two 16 KB buffers; Caddy needed more than 128 MiB at 5,000 sockets. Its health check sends HTTP/1.1 with a `Host`: the API answers 500 to a request with none. It stands for Traefik, not for it.
- A change to the API's drain, `/api/health` or the close codes changes what the handoff run shows: rerun both runs and update the evidence file, with the date and commit.
