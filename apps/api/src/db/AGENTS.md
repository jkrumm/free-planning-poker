# apps/api/src/db

The Postgres schema `fpp`, its repositories, and the adapters on them. Repositories are plain functions that take a `db` (a `Db` or a transaction, type `Executor`) and an explicit `now`, so a test needs no sleep; they import no Effect. The adapters wrap them in Effect: `resilience.ts` (the pool, `DbUnavailable` against `DbDefect`, the retry schedules, the per-room serial queue), `store.ts` (the `RoomStore` port) and `history.ts` (the `History` port). Nothing here imports Elysia or reads the environment.

- **Every query goes through `Database.run`**, never a `Db` held elsewhere: Bun 1.4's pool sometimes stays broken after an outage (`connection must be a PostgresSQLConnection` until restart), so a connection error replaces the pool. Retry only `DbUnavailable`, with `retryWhileDown` for a write and `retryBriefly` (2 s) for a caller who waits; any other error is a bug and is never retried.
- **One room's writes run in order** (`serialQueue`): a round names its topic, so the queue write of a step lands first. A retried write must be idempotent: `insertRound` skips a stored round id.
- **Prove a change to the adapters with the server tests in `apps/api/test`**: `persistence` (in process), `handoff` (SIGTERM and SIGKILL mid-round, two processes), `processes` (the epoch fence between two processes), `outage` (Postgres stopped for 60 s; about 70 s of wall time).
- **Schema change:** edit `schema.ts`, then `bun run --filter @fpp/api db:generate`. `migrations.test.ts` (check-fast) fails on drift. Two lines of `0000_init.sql` are hand edits because drizzle cannot express them: `CREATE UNLOGGED TABLE room_snapshot` and `CREATE SCHEMA IF NOT EXISTS` (the migrator creates `fpp` for its journal first). A later migration is generated untouched.
- **Statements with `ON CONFLICT` are raw SQL** (`addresses.ts`, `rooms.ts`, `topics.ts`): the claim, the book and the snapshot write each decide in one statement, which is what the concurrency tests prove. Keep each one statement.
- **bun-sql returns a raw result as the row array, a bigint as a string and jsonb as text unless the column is selected through Drizzle.** Convert with `Number()` and `::text` plus `JSON.parse`, as `rooms.ts` does; pass an object, never `JSON.stringify(...)`, to a `::jsonb` parameter (a string is stored as a JSON string).
- **A write is fenced by epoch and owner** (invariant 12): a snapshot written by a process whose claim another process has since replaced changes no row and returns `lost`. An expired snapshot is not restored. The epoch lives in the snapshot row, so the sweep resets it: the owner match alone then fences, which is why an owner id must be unique per process, and an owner idle past the sweep gets `lost` on its next write although nobody claimed the room.
- **No statement deletes a room, a round or a vote**; `store.server.test.ts` reads these sources for it. The scheduled deletions are expired snapshots and `visitor_day` rows older than 13 months; the one other is a topic the room removed from its queue, which only a queued topic no round names can be (`writeQueue`).
- Hold periods and the snapshot lifetime are the constants of `holds.ts`. Use nothing newer than PostgreSQL 16.
