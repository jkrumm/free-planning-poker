# apps/room

The room app: a Vite SPA, client only, served by the API under `/room` and `/_room` (`docs/v9/ARCHITECTURE.md`, Topology and Client). Until `v9-ui-foundation` it is plain HTML with no look: semantic elements, source order, no CSS. Its `data-testid`s outlive the redesign: `e2e/TESTIDS.md`.

## Where things are

| Path | Holds |
|-|-|
| `src/main.tsx` | the shell: reads the window once into an `AppEnv`, activates the language, mounts the router |
| `src/app-env.tsx` | `AppEnv` (ports, storage, fetch, hash, language activation) and its provider; a test passes its own |
| `src/routes/` | file routes: `/room`, `/room/new`, `/room/$slug`; `routeTree.gen.ts` is generated by `vite build` and committed |
| `src/features/<name>/` | one directory per feature; `language`, `lobby`, `room`; `room/use-room.ts` is the one hook that binds `@fpp/room-client` |
| `test/` | component tests under Bun on happy-dom: the real room runtime in memory (`harness.tsx`), one app per seat |

## Rules

- **Every visible string is a message** (`t`, `plural`, `msg` from Lingui's macros), in English and German in the same change: rule `strings.md`, `packages/i18n/AGENTS.md`. Literal JSX text fails oxlint; a literal in `aria-label`, `placeholder`, `title` or `alt` fails the message check.
- **Name a value before a message uses it** (``const name = seat.name`` first, then ``t`Remove ${name}` ``): a member expression becomes the placeholder `{0}`, which a translator cannot read.
- **Nothing here reads `window`, `document` or storage but `main.tsx`**; components take `useAppEnv()`. That is what lets the tests run the app on the simulator's network and clock.
- **A new element a person can use gets a `data-testid`** and a row in `e2e/TESTIDS.md`; the room test fails otherwise.
- No `basalt-ui`, Tailwind or CSS here yet (a test greps for them); no browser telemetry; no dev server (`bun run dev` is the owner's).
- The entry JavaScript is at most 130 kB gzip (`scripts/budget.ts`, run by `make build`); a language's catalogue files load on demand and do not count. Report the number in the pull request.

## Tests

- A test file that renders imports `./dom.ts` first and loads `./harness.tsx` with a dynamic `import()` after it: React decides at load time whether the page supports `input` events, so a DOM that arrives later is never seen. Its `afterAll` unregisters the DOM so other tests keep Bun's `fetch` and timers.
- `test/lingui-bun.ts` (preload in `bunfig.toml`) compiles the Lingui macros and `.po` files for Bun; the app itself builds with `@lingui/vite-plugin`.
- Time moves with `world.advance(ms)`; no test sleeps. Type into a field with `seat.type` and submit with `seat.submit`: happy-dom does not submit a form on a button's click.
